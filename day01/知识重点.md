# Day 1 知识重点：变量、数据类型、类型转换

> 定位：这是整个月的"地基"。C++ 程序员学 JS 的核心转变只有一句话——
> **C++ 是"变量有类型"，JS 是"变量没类型、值有类型"。**

---

## 一、变量声明：let / const（var 已淘汰）

### 1. 三选一规则（就这么简单）

| 关键字 | 能否重新赋值 | 能否重复声明 | 作用域 | 使用场景 |
|--------|------------|------------|--------|---------|
| `const` | ❌ | ❌ | 块级 | **默认选择** |
| `let` | ✅ | ❌ | 块级 | 确实需要重新赋值时 |
| `var` | ✅ | ✅ | 函数级 | **不要用**（遗留语法） |

```js
let score = 90;
score = 95;         // ✅
const PI = 3.14;
PI = 3.15;          // ❌ TypeError: Assignment to constant variable
```

### 2. const 的真正含义（练习 5 的核心）

**const 锁的是"引用"，不是"内容"**：

```js
const user = { name: "A" };
user.name = "B";        // ✅ 合法！对象内部随便改
user = { name: "C" };   // ❌ 报错！不能让 user 指向别的对象
```

类比 C++：`const user` ≈ `User* const user`（指针本身是常量），而不是 `const User*`（指向常量）。

### 3. 块级作用域

`let` / `const` 只在 `{}` 内有效，出块即销毁——和 C++ 一致，这是 `var`（函数作用域、会泄漏）被淘汰的主因。

## 二、数据类型：7 + 1 体系

### 1. 总览

**原始类型 7 种**（按值访问）：`number`、`string`、`boolean`、`undefined`、`null`、`bigint`、`symbol`
**引用类型 1 种**：`object`（对象、数组、函数都算它）

查看类型用 `typeof` 运算符。

### 2. number：只有一种数字类型

- 所有数字都是 64 位浮点（≈ C++ 的 `double`），**没有 int / float / long 之分**
- `10 / 3 === 3.333...`（没有整数除法！）
- 浮点精度：`0.1 + 0.2 === 0.3` 为 `false`（和 C++ double 同源的问题，但 JS 不会帮你四舍五入显示）
- 整数精度上限 2^53，超了用 `bigint`（字面量后缀 `n`）
- 特殊值：`NaN`（不是数）、`Infinity`（无穷）

### 3. string：不可变

- 没有 `char` 类型，单字符就是长度 1 的字符串
- **不可变**（同 Java/C#）：`s.toUpperCase()` 不改变原串，必须接收返回值
- 模板字符串是标配：`` `你好, ${name}!` ``（反引号 + `${}` 插值，可跨行）
- 常用方法：`length`、`slice(start, end)`、`includes`、`indexOf`、`split`、`join`、`replace`、`trim`、`toUpperCase/toLowerCase`

### 4. boolean 与 truthy / falsy

JS 的 `if` 不要求条件是布尔值，**任何值都能判断**：

- **falsy 只有 6 个**：`false, 0, "", null, undefined, NaN`
- 其余全是 truthy，**包括 `"0"`、`[]`、`{}`、负数、小数**

⚠️ C++ 直觉失灵重灾区：`"0"` 在 C++ 里当指针是"真"，当数值 0 是"假"，JS 里它就是 truthy 字符串。

### 5. undefined vs null（语义区分）

| 值 | 含义 | 类比 |
|----|------|------|
| `undefined` | 系统级的"没值"：声明未赋值、访问不存在的属性、函数没写 return | 未初始化变量 |
| `null` | 程序员**主动**放的"空" | `nullptr` |

彩蛋：`typeof null === "object"` 是历史遗留 bug，改不了，背下来。

### 6. object：动态的"结构体 + map"

```js
const user = { name: "huiwei", age: 30 };   // 字面量创建，无需预定义字段
user.email = "x@y.com";                     // 直接加字段
console.log(user.name, user["age"]);        // 点访问 / 方括号访问
```

⚠️ 对象和数组**按引用传递**；数组越界**不报错**，返回 `undefined`（C++ 未定义行为，JS 温柔但藏 bug）。

## 三、类型转换

### 1. 铁律：一律用 === 和 !==，忘掉 ==

```js
1 == "1"          // true  （== 偷偷把字符串转数字）
1 === "1"         // false （=== 先比类型，类型不同直接不等）
null == undefined // true  （特殊规则）
null === undefined// false
```

### 2. 三个转数字函数的取舍（练习 3 的核心）

| 函数 | `"100"` | `"20px"` | `""` | `"abc"` | 用途 |
|------|---------|----------|------|---------|------|
| `Number(x)` | 100 | **NaN** | **0** | NaN | 严格转换，整串必须合法 |
| `parseInt(x, 10)` | 100 | 20 | **NaN** | NaN | 从头解析，遇非数字停止 |
| `parseFloat(x)` | 100 | NaN | NaN | NaN | 同上，支持小数 |

三个必背的特殊点：
- `Number("") === 0`（空串是 0，不是 NaN！）
- `Number("20px") === NaN`（带单位转不了，用 parseInt）
- `parseInt("") === NaN`

### 3. NaN 的三个特性

1. `NaN === NaN` 为 `false`——它不等于任何值包括自己
2. 判断 NaN 只能用 `Number.isNaN(x)`
3. **NaN 会传染**：`NaN + 1 === NaN`，任何运算混入 NaN 结果都是 NaN

### 4. 转字符串 / 转布尔

```js
String(123)         // "123"
(123).toString()    // 同上
(3.14159).toFixed(2) // "3.14" —— 注意返回的是字符串！
Boolean(0)           // false，规则同 truthy/falsy
```

### 5. + 运算符的双面性（经典 bug 来源）

```js
"1" + 1        // "11"   有字符串就全转字符串拼接
1 + 1          // 2
"5" - 2        // 3      - 只能算数字，会转
input + 50     // "10050" 输入框拿到的都是字符串，先 Number() 再算！
```

快捷转换：`+"42"` 得到 42（一元 +）；去小数用 `Math.trunc(3.99)` 而非 `~~`。

## 四、Day 1 易错点清单（自测）

1. `typeof null` 是什么？（→ `"object"`，历史 bug）
2. `10 / 3` 是多少？（→ `3.333...`，没有整数除法）
3. `"0"` 是 truthy 还是 falsy？（→ truthy）
4. `Number("")` 和 `parseInt("")` 分别是多少？（→ `0` / `NaN`）
5. `NaN === NaN` 是多少？（→ `false`，判断用 `Number.isNaN`）
6. `const arr = [1,2]; arr.push(3);` 会报错吗？（→ 不会，const 只锁引用）
7. `"1" + 1` 和 `"1" - 1` 分别是多少？（→ `"11"` / `0`）
8. `toFixed` 返回什么类型？（→ 字符串）
